Gradient Descent : A hill climb problem

That's what every professor says when teaching about GD to give some intuitive sense but do we really have understood it intuitively. Let's build a complete physical analogy that maps every GD concept to fluid dynamics, then use this to understand (and improve) optimizers

1. Physical Mapping

Lets try to map out GD to water flowing down the hills and then use the intuitive notions of fluid dynamics to derive our analogy that work for the GD

GRADIENT DESCENT              WATER DYNAMICS
─────────────────────────────────────────────────
Loss function L(θ)        =   height h(x,y)
Parameters θ              =   Water drop position
Gradient ∇L              =   Slope of hill
Learning rate α           =   Inverse of viscosity (fluid thickness)
Momentum                  =   Mass inertia
Learning rate decay       =   Increasing viscosity over time
Local minimum             =   Pond (stable equilibrium)
Saddle point              =   Mountain pass or gorges (unstable equilibrium)
Global minimum            =   Ocean (lowest point)  which is our goal

2. Governing equations:

Water flowing downhill (simplified Navier-Stokes):

$$ Acceleration = Gravitational force - Friction $$

$$\frac{dv}{dt} = -g \sin(\phi) - \mu v$$

Where: - v = velocity - g = gravitational acceleration
- θ = terrain slope - μ = friction/viscosity coefficient

and then we have two variants of GDs

i. Vanilla Gradient Descent (The Overdamped case)

Standard gradient descent updates parameters strictly based on the local, instantaneous slope:

$$\theta_{new} = \theta_{old} - \alpha \nabla L(\theta_{old})$$

In continuous time, by taking the step size $\Delta t \to 0$, this yields a first-order differential equation:

$$\frac{d\theta}{dt} = -\alpha \nabla L(\theta)$$

Physically, this represents the extreme high-viscosity limit ($\mu \to \infty$) where viscous drag completely dominates and kills mass. acceleration drops to zero instantaneously ($\frac{dv}{dt} = 0$), meaning velocity is directly proportional to force ($v \propto F$). The moment the slope hits zero, the system stops dead with zero momentum memory as if it has no inertia.

ii. Momentum Gradient Descent (The Inertial case)

To simulate the physical mass and momentum of water, we introduce a velocity memory buffer $v$:

$$v_{new} = \beta v_{old} - \alpha \nabla L(\theta_{old})$$ $$\theta_{new} = \theta_{old} + v_{new}$$

By taking the continuous-time limit ($\Delta t \to 0$) and letting $\beta = 1 - \mu \Delta t$, this discrete system cleanly reveals itself as a second-order differential equation (identical to a damped harmonic oscillator):

$$\frac{d^2\theta}{dt^2} + \mu \frac{d\theta}{dt} = -\alpha \nabla L(\theta)$$

This matches our physical fluid equation perfectly. The parameters now possess real mass, allow the system to accelerate down steep slopes, and provide the kinetic energy necessary to overshoot narrow local minima.

3. Code to equations

Equations on a page don't overshoot anything. To actually see the overdamped case crawl and the inertial case overshoot, we need real terrain and a real droplet sitting on it.

Two things that moves everything in our space:

  • $L(\theta)$ itself : the hill. We'll use a friendly paraboloid bowl first, purely to check whether our slope fucntion is working correctly, then switch to a bumpy Rastrigin surface (a space with lots of local minima and one global minimum defined by (f(x) = An + \sum_{i=1}^n [x_i^2 - A \cos(2\pi x_i)])).
  • $\nabla L(\theta)$ : the slope gradient. Rather than differentiating each hill by hand, we let the computer estimate it directly from the hill's height a tiny step in each direction whcih enable the fucntion to find slope for in any direction on any terrain
import numpy as np

def bowl(x, y):
    return x**2 + y**2

def rastrigin(x, y):
    return (x**2 + y**2) - 10 * (np.cos(2*np.pi*x) + np.cos(2*np.pi*y)) + 20

def slope(L, x, y, eps=1e-5):
    dL_dx = (L(x + eps, y) - L(x - eps, y)) / (2 * eps)
    dL_dy = (L(x, y + eps) - L(x, y - eps)) / (2 * eps)
    return np.array([dL_dx, dL_dy])

# Let's test the functioning of fucntion with the bowl's true gradient [2x, 2y]:
for x, y in [(1.0, 1.0), (2.5, -1.3), (-3.0, 4.0)]:
    print(f"slope{(x,y)} = {slope(bowl, x, y).round(4)}   true = {[2*x, 2*y]}")

slope(1.0, 1.0) = [2. 2.]   true = [2.0, 2.0]
slope(2.5, -1.3) = [ 5.  -2.6]   true = [5.0, -2.6]
slope(-3.0, 4.0) = [-6.  8.]   true = [-6.0, 8.0]

Yeah they are somewhat agreeing and as such the slope() can be trusted on the bumpier rastrigin terrain that we are going to drop in.

4. Simulating the water droplet

This is $\theta_{new} = \theta_{old} - \alpha \nabla L(\theta_{old})$ and its momentum as seen from section 2, something that is simulating the real physical phenomena. Onestep() with $\beta = 0$ it's the overdamped case and any $\beta > 0$ and it's the inertial one.

class Droplet:
    def __init__(self, x0, y0, alpha=0.01, beta=0.0):
        self.theta = np.array([x0, y0], dtype=float)
        self.v = np.zeros(2)
        self.alpha = alpha
        self.beta = beta
        self.path = [self.theta.copy()]
        self.heights = []

    def step(self, L):
        grad = slope(L, *self.theta)
        self.v = self.beta * self.v - self.alpha * grad
        self.theta = self.theta + self.v
        self.path.append(self.theta.copy())
        self.heights.append(L(*self.theta))
        return self.theta

    def flow(self, L, n_steps):
        for h in range(n_steps):
            self.step(L)
        return self.theta

Let's see how the two cases beahave on the plain bowl where we know the answer is the origin.

overdamped = Droplet(3.0, 4.0, alpha=0.1, beta=0.0)
overdamped.flow(bowl, 100)

inertial = Droplet(3.0, 4.0, alpha=0.1, beta=0.9)
inertial.flow(bowl, 100)

overshoots = (np.diff(inertial.heights) > 0).sum()
print(f"overdamped (beta=0)   settles at {overdamped.theta.round(4)}, never once overshoots")
print(f"inertial   (beta=0.9) settles at {inertial.theta.round(4)}, overshoots {overshoots} times on the way down")

overdamped (beta=0)   settles at [0. 0.], never once overshoots
inertial   (beta=0.9) settles at [-0.0086 -0.0114], overshoots 45 times on the way down

Behaving as predicted $\beta=0$ glides straight in and stops dead the instant the slope flattens with no memory, no overshoot. $\beta=0.9$ carries momentum and oscillates back and forth before settling, the damped-oscillator behaviour.

5. Real terrain - The analogy for step size thing

The bowl was just a check. Let's actually drop the overdamped droplet onto the rippled Rastrigin terrain and see what is this damping gives us.

Naively we can say that bigger $\alpha$ (thinner fluid, less viscous) just means faster but sloppier descent, and smaller $\alpha$ means slower but safer - representing respectively water and honey. Let's actually check that assumption.

safe = Droplet(2.5, 2.5, alpha=0.005, beta=0.0)
safe.flow(rastrigin, 300)

reckless = Droplet(2.5, 2.5, alpha=0.05, beta=0.0)
reckless.flow(rastrigin, 300)

worse_steps = (np.diff(reckless.heights) > 1e-6).sum()
print(f"alpha=0.005: settles at {safe.theta.round(3)}, height {safe.heights[-1]:.2f}")
print(f"alpha=0.05:  ends up at {reckless.theta.round(3)}, height {reckless.heights[-1]:.2f}"
      f"  -- got WORSE on {worse_steps}/299 steps")

alpha=0.005: settles at [1.99 1.99], height 7.96
alpha=0.05:  ends up at [-3.647 -3.647], height 58.70  -- got WORSE on 149/299 steps

At alpha=0.05 the droplet's step is larger than the spacing between ponds, so instead of rolling downhill it leaps over several ripples every time and lands somewhere close to random. It gets worse on over half the steps (149/299).

There's some real thershold in the terrain's own dynamics as in below roughly alpha=0.01 the droplet flows properly and above it, the "water" analogy breaks down entirely and it can better be described as a droplet in an earthquake.

Here the Over damping is occuring for honey as such it has no inertia, so it can never overshoot which is what "high viscosity" actually means. If we want something that behaves like actual water, with real momentum, that's the $\beta>0$ case from Section 4, not this one.

6. Momentum's own Goldilocks zone

If honey (over damped one) gets stuck in the first pond it finds, does adding inertia always help? Let's sweep $\beta$ at the same safe $\alpha$ and see it for ourselves.

for beta in [0.0, 0.5, 0.8, 0.9, 0.95, 0.99]:
    d = Droplet(2.5, 2.5, alpha=0.005, beta=beta)
    d.flow(rastrigin, 300)
    print(f"beta={beta:<5} settles at {d.theta.round(3)}  height={d.heights[-1]:7.3f}")

beta=0.0   settles at [1.99 1.99]  height=  7.960
beta=0.5   settles at [1.99 1.99]  height=  7.960
beta=0.8   settles at [1.99 1.99]  height=  7.960
beta=0.9   settles at [0.995 0.995]  height=  1.990
beta=0.95  settles at [2.984 2.984]  height= 17.909
beta=0.99  settles at [-10.009 -10.009]  height=200.391

Note that the global minima of rastrigin function is located at (0,0) as such see which is sweeping closer towards it

So momentum has its own overdamped/inertial spectrum in miniature:

  • $\beta \le 0.8$ : not enough kinetic energy to climb out of the first pond; same result as no momentum at all.
  • $\beta = 0.9$ : just enough energy to climb the far wall of its pond and roll into a genuinely deeper one nearby.
  • $\beta = 0.95$ : overshoots past the good pond into a worse one.
  • $\beta = 0.99$ : so much inertia it never settles anywhere; same species of chaos as the reckless $\alpha$ above, just caused by too much mass instead of too big a step.

Inertia is a resource with a cost, not a strict improvement which is exactly the same shape of trade-off as viscosity had, and worth noting as a matched pair in the writeup.

7. Watching the flow

One picture, worth the thousand words above. Note the deliberately asymmetric starting point... the Rastrigin surface here is separable ($L(x,y) = f(x) + f(y)$, no cross-term), so a symmetric start collapses every path onto one diagonal line and hides exactly the divergence we want to see.

8. Saddle points

The pond-and-ocean picture from Section 1 also names saddle points as mountain passes or some stable plain space.. unstable equilibria where the surface curves up in one direction and down in another. The textbook claim is usually: plain GD gets stuck balanced on the pass, and only momentum can knock it off.

Worth testing before repeating it. Take the cleanest possible saddle, $L(x,y) = x^2 - y^2$, and start a droplet of a minute value from the exact pass:

saddle = lambda x, y: x**2 - y**2

print("plain GD (beta=0), started at (0.01, 0.01):")
for n in [10, 50, 100]:
    d = Droplet(0.01, 0.01, alpha=0.1, beta=0.0)
    d.flow(saddle, n)
    print(f"  after {n:3d} steps, |y| = {abs(d.theta[1]):.4f}")

print()
print("momentum (beta=0.9), same start:")
for n in [10, 50, 100]:
    d = Droplet(0.01, 0.01, alpha=0.1, beta=0.9)
    d.flow(saddle, n)
    print(f"  after {n:3d} steps, |y| = {abs(d.theta[1]):.4f}")

print()
d_exact = Droplet(0.0, 0.0, alpha=0.1, beta=0.0)
d_exact.flow(saddle, 500)
print("started EXACTLY at the pass (0,0):", d_exact.theta, "-- truly never moves, zero slope")

plain GD (beta=0), started at (0.01, 0.01):
  after  10 steps, |y| = 0.0619
  after  50 steps, |y| = 91.0044
  after 100 steps, |y| = 828179.0520

momentum (beta=0.9), same start:
  after  10 steps, |y| = 0.3845
  after  50 steps, |y| = 4250827.5594
  after 100 steps, |y| = 804109874204.1071

started EXACTLY at the pass (0,0): [0. 0.] -- truly never moves, zero slope

So the textbook line needs an asterisk. Plain GD is only a true fixed point if it starts exactly on the pass ... a razor's-edge coincidence that never happens in practice (any floating-point noise nudges it off). Given the tiniest nudge, plain GD does slide off the pass and down into the unbounded direction.. it just takes longer to build speed than momentum does. By 50 steps, momentum is already ~46,000× further down the slope than plain GD.

So rather we can say something like this maybe momentum doesn't rescue GD from a mountain pass.. it just gets off it faster.

9. Adam optimiser

Section 1's mapping treats viscosity as one global dial. But real terrain is rarely equally steep in every direction.. picture a gorge, steep walls either side, sloped along its length. A single viscosity has to compromise: cautious enough not to slam into the walls, which makes it crawl along the gorge's length.

Adam is water that sets its own local viscosity per direction .. thick where the slope is steep, thin where it's flat:

$$m_t = \beta_1 m_{t-1} + (1-\beta_1)\nabla L, \qquad v_t = \beta_2 v_{t-1} + (1-\beta_2)(\nabla L)^2$$ $$\theta_{new} = \theta_{old} - \alpha \frac{\hat m_t}{\sqrt{\hat v_t} + \epsilon}$$

where $\hat m_t, \hat v_t$ are bias-corrected versions of $m_t, v_t$.

class AdamDroplet:
    def __init__(self, x0, y0, alpha=0.01, beta1=0.9, beta2=0.999, eps=1e-8):
        self.theta = np.array([x0, y0], dtype=float)
        self.m = np.zeros(2)
        self.v = np.zeros(2)
        self.alpha, self.beta1, self.beta2, self.eps = alpha, beta1, beta2, eps
        self.t = 0
        self.heights = []

    def step(self, L):
        self.t += 1
        grad = slope(L, *self.theta)
        self.m = self.beta1 * self.m + (1 - self.beta1) * grad
        self.v = self.beta2 * self.v + (1 - self.beta2) * grad**2
        m_hat = self.m / (1 - self.beta1**self.t)
        v_hat = self.v / (1 - self.beta2**self.t)
        self.theta = self.theta - self.alpha * m_hat / (np.sqrt(v_hat) + self.eps)
        self.heights.append(L(*self.theta))
        return self.theta

    def flow(self, L, n_steps):
        for _ in range(n_steps):
            self.step(L)
        return self.theta

# gorge
gorge = lambda x, y: x**2 + 100*y**2

honey_in_gorge = Droplet(3.0, 3.0, alpha=0.009, beta=0.0)
honey_in_gorge.flow(gorge, 200)

smart_water = AdamDroplet(3.0, 3.0, alpha=0.1)
smart_water.flow(gorge, 200)

print(f"honey  (alpha=0.009, its stability limit): height={honey_in_ravine.heights[-1]:.4f}")
print(f"Adam   (alpha=0.1, 10x larger):            height={smart_water.heights[-1]:.4f}")

honey  (alpha=0.009, its stability limit): height=0.0063
Adam   (alpha=0.1, 10x larger):            height=0.0000

Adam converges to essentially zero with a larger nominal $\alpha$ than honey can even survive at. That's the mechanism made robust where it's thick in the steep direction and thin in the flat one, simultaneously, which plain viscosity can never do with one shared dial.

10. Annealing in SGD

Section 1 maps a decaying learning rate to "increasing viscosity over time." Tried the obvious way.. start already-safe and decay further.. and it changes nothing, because the droplet has already settled into its first pond within a handful of steps; cooling something that already stopped moving does nothing.

The version that matters is the opposite order: start reckless (chaotic with large alpha, exploring many ponds), then cool into caution ..actual simulated annealing.

schedules = {
    "always reckless":    lambda t: 0.05,
    "always cautious":    lambda t: 0.005,
    "reckless -> cautious (annealed)": lambda t: 0.005 + 0.045 * np.exp(-0.02 * t),
}
for name, alpha_fn in schedules.items():
    d = Droplet(2.5, 1.7, alpha=alpha_fn(0), beta=0.0)
    for t in range(300):
        d.alpha = alpha_fn(t)   # re-set viscosity each step, straight from the schedule
        d.step(rastrigin)
    print(f"{name:<35} height={d.heights[-1]:.3f}")

always reckless                     height=34.242
always cautious                     height=7.960
reckless -> cautious (annealed)     height=5.079

Annealing beats staying cautious the whole time. Starting hot lets the droplet sample several ponds before it has to commit to one; cooling down afterward means it settles wherever that exploration left it.... which tends to beat greedily taking the very first pond it stumbles into.

11. SGLD (Stochastic Gradient Langevin Dynamics)

Section 3's ripple-terrain chaos and Section 10's annealing both hint at something noise-like happening. It's an established equivalence: Welling & Teh (2011), Bayesian Learning via Stochastic Gradient Langevin Dynamics, and Mandt, Hoffman & Blei (2017), Stochastic Gradient Descent as Approximate Bayesian Inference, show that gradient descent with calibrated noise behaves like a real thermodynamic system at temperature $T$:

$$\theta_{new} = \theta_{old} - \alpha \nabla L(\theta_{old}) + \sqrt{2\alpha T}\,\xi, \qquad \xi \sim \mathcal{N}(0, I)$$

$T=0$ collapses this back to plain GD exactly.

class HeatedDroplet:
    def __init__(self, x0, y0, alpha=0.005, T=0.0, seed=0):
        self.theta = np.array([x0, y0], dtype=float)
        self.alpha, self.T = alpha, T
        self.rng = np.random.default_rng(seed)
        self.heights = []

    def step(self, L):
        grad = slope(L, *self.theta)
        noise = self.rng.normal(size=2) * np.sqrt(2 * self.T * self.alpha)
        self.theta = self.theta - self.alpha * grad + noise
        self.heights.append(L(*self.theta))
        return self.theta

    def flow(self, L, n_steps):
        for _ in range(n_steps):
            self.step(L)
        return self.theta

for T in [0.5, 1.0, 2.0, 5.0, 10.0]:
    escapes, finals = 0, []
    for seed in range(20):
        d = HeatedDroplet(2.5, 1.7, alpha=0.005, T=T, seed=seed)
        d.flow(rastrigin, 1000)
        finals.append(d.heights[-1])
        if d.heights[-1] < 5.0:
            escapes += 1
    print(f"T={T:<5} escaped its starting pond {escapes:2d}/20 times, mean final height={np.mean(finals):6.2f}")

T=0.5   escaped its starting pond  0/20 times, mean final height= 12.75
T=1.0   escaped its starting pond  0/20 times, mean final height= 14.16
T=2.0   escaped its starting pond  2/20 times, mean final height= 11.42
T=5.0   escaped its starting pond  2/20 times, mean final height= 19.38
T=10.0  escaped its starting pond  0/20 times, mean final height= 35.58

The real statistical-mechanics story, with numbers behind it: too cold (T=0.5–1) and it never has the energy to climb out; a middle temperature (T=2–5) occasionally escapes to somewhere better; too hot (T=10) and it never settles anywhere at all... its average outcome is worse than doing nothing, because it's now just wandering.

That's the real story of why a little noise in training (like using small mini-batches, which is naturally noisy) can help escape bad spots, but too much noise just prevents the model from ever converging.

12. Lil crooked animation

Everything above has been end-states and single snapshots. Here's a version that actually plays, frame by frame — honey gliding straight in and stopping, momentum visibly looping before it settles.

from matplotlib.animation import FuncAnimation, PillowWriter

start, n_steps = (2.5, 1.7), 150
cast = {
    "honey, beta=0":      ("white",  Droplet(*start, alpha=0.005, beta=0.0)),
    "momentum, beta=0.9": ("orange", Droplet(*start, alpha=0.005, beta=0.9)),
}
for _, d in cast.values():
    d.flow(rastrigin, n_steps)

xs = ys = np.linspace(-4, 4, 250)
X, Y = np.meshgrid(xs, ys)
Z = rastrigin(X, Y)

fig, ax = plt.subplots(figsize=(7, 6))
ax.contourf(X, Y, Z, levels=40, cmap="viridis")
ax.scatter(0, 0, color="cyan", marker="*", s=200, edgecolor="black", zorder=6, label="the ocean")
ax.set_xlim(-4, 4); ax.set_ylim(-4, 4)
dots, trails = {}, {}
for name, (color, d) in cast.items():
    (dot,)   = ax.plot([], [], "o", color=color, ms=10, mec="black", label=name)
    (trail,) = ax.plot([], [], color=color, lw=1, alpha=0.6)
    dots[name], trails[name] = dot, trail
ax.legend(loc="upper left", fontsize=8)

def frame(i):
    for name, (_, d) in cast.items():
        p = np.array(d.path[:i+1])
        dots[name].set_data([p[-1,0]], [p[-1,1]])
        trails[name].set_data(p[:,0], p[:,1])
    ax.set_title(f"step {i}")
    return list(dots.values()) + list(trails.values())

anim = FuncAnimation(fig, frame, frames=n_steps+1, interval=50)
anim.save("droplets.gif", writer=PillowWriter(fps=20))

But why?

Despite all these tropes why is that the droplets are not reaching the ocean still? Cause none of these techniques (momentum, annealing, noise, Adam) guarantee finding the global minimum. What they do is improve your odds of finding something better than the laziest possible answer. This maps directly onto real neural network training: nobody training a real model ever verifies they've hit the true global minimum across millions of parameters... it's not even computationally checkable. In practice, training accepts "a good enough local minimum" as success, and the entire reason optimizers like momentum and Adam exist is to make that local minimum as good as reasonably possible, not to guarantee perfection

13. Where the analogy bends

  • This terrain is separable ($L(x,y)=f(x)+f(y)$)... there's no real coupled diagonal flow here, x and y are secretly two independent 1-D problems. A real loss surface, and a truly diagonal-flow demo, needs a cross term.
  • Real loss landscapes live in thousands or millions of dimensions, not two. Intuition built on a 2-D hill doesn't automatically transfer.
  • "Temperature" is only a literal, calibrated thing when you deliberately add SGLD-style noise, as in Section 11. Ordinary mini-batch noise is temperature-like, not identical to it.
  • Parameters don't have real mass... momentum is a useful bookkeeping trick that behaves like inertia, not literal inertia.
